# CreVa: handoff

Last updated 2026-10-11 (after the first Vercel deploy). For whoever (or whichever session) picks this up next.

## 1. Goal

A working prototype of **CreVa** for a product management assignment: a creator-only dashboard for Indian micro-influencers (10K to 100K followers). It tells a creator what a specific brand offer is worth, what rights the contract takes, and how to negotiate it. A rate card prices an audience; a valuation prices what a specific brand is taking. CreVa separates content value from rights value.

Rules that must hold:
- Every AI output carries a **range**, **confidence** (High/Medium/Low), **evidence tier** and deal count, and **what it does not know**.
- CreVa never accepts, signs or sends anything. No send button anywhere. Drafts are editable and copy-only.
- It explains commercial consequences, not legal validity.
- "I don't have enough evidence" is a valid answer (Post Autopsy).
- Paid partnership disclosure is included or flagged on anything drafted.
- Everything must stay free: Groq, Supabase, Vercel, GitHub free tiers only.
- No secret ever goes in the repo, a commit, a log, an error message or chat.

Hero numbers, identical everywhere: GlowSkin offers ₹30,000. Indicative ₹70,000. Fair range ₹62,000 to ₹70,000. Counter ₹68,000 (₹55,000 and ₹32,000 for the other modes). Closed at ₹58,000. 4 contract issues. Content ₹47,000, rights ₹25,000. Medium confidence, Tier 2, 12 deals (median ₹54,000).

## 2. Current state

### Architecture
- `counter.html` is the whole front end and the single source of truth (HTML, CSS, vanilla JS). `scripts/build.js` wraps it into `public/index.html` (generated, git-ignored).
- `scripts/gen-engine.js` copies the pure pricing engine and the system prompt out of `counter.html` into `lib/engine.js` and `lib/system.js` (committed; `npm test` fails if they go stale). **The server uses the same engine as the browser.**
- `api/*.js` are Web-standard handlers (`export default { fetch(request) }`) that run on Vercel and locally (`server.js` mounts them, binds 127.0.0.1 only, loads `.env.local`).
  - `api/ai.js` Groq proxy. Tasks: deal, contract, negotiate, autopsy, checker. **The engine owns every number; the model only explains.** Guardrails run before any model call. Per-IP limit (best effort, in memory), daily cap counted in the database, 20 s timeout, no retries, same-origin only.
  - `api/data.js` Supabase reads/writes through the service role key (server only): `kind=bootstrap`, `profile`, `contract`, `eval`. Validated, capped, 4 s database timeout.
  - `api/keepalive.js` tiny database read, called daily by a Vercel cron job.
  - `api/health.js` liveness.
- `lib/` shared server code: `groq.js`, `supabase.js`, `validate.js` (schemas and reconciliation), `data.js` (validation and mapping), `limits.js`, `wrap.js`.
- `supabase/schema.sql` + `supabase/seed.sql` (generated by `scripts/gen-seed.js`). Row level security is on for every table with no policies, so the browser can never reach the database directly. The 12 network deals are **synthetic** (`is_synthetic = true`), median 54,000.

### Front end behaviour
- Runs on seeded in-memory data if the database or the model is unavailable, with honest labels: "Live model (Groq, <model>). Numbers checked by CreVa engine." or "Fallback engine, not the live model (<human reason>)". Profile shows "Demo data (database offline)" when the database is down.
- Inside the Claude artifact it still uses the artifact `sample` capability; on a real site it uses `/api/ai`.
- Guardrails (`refusal()`, `special()`) run in the browser first.
- Loads `/api/data?kind=bootstrap` on start; autosaves the profile only when changed (2 s debounce tick); saves contracts and issue states on change; Stop button aborts an analysis; "Recent analyses" on Deal Intelligence.
- Screens: Home, Ask CreVa (rule-based answers to questions that are not offers), Opportunities, Deal Intelligence, Breakdown, Contracts (list by brand, issue actions Reviewed/Clear/Dismiss that update every screen), Negotiate, Deals, Payments, Growth (Post Autopsy), Public rate checker, Profile (illustrated avatar, simulated social linking). Tour, speech to text (EN/हि), dark (violet) and light (gold) themes.

## 4. Things tried that failed (do not repeat)
- **Backslashes in bash heredocs and patch scripts get collapsed.** Use Edit/Write for anything with backslashes or regex. Do not patch `counter.html` with sed/python.
- **Groq strict schemas and lengths:** Groq checks the model's output against the schema after generation and answers 400 `json_validate_failed` for near-misses. `maxLength`/`maxItems` on free text threw away good answers, so limits are applied on the server. The exception is arrays keyed to the engine's risk keys: keep `maxItems` there, otherwise the model invents a fifth issue.
- The engine tags payment-terms lines `group: "finance"`; the schema must allow it.
- **Model drift:** gpt-oss-20b sometimes writes "unlimited revisions", causal language in autopsies, or headlines that bury the licence. Server-side guards reject or replace these (draft faithfulness check, `BLAME` regex, `headlineKeepsPriority`). Expect an occasional fallback label.
- An unreachable Supabase took 7 s to fail; calls are now capped at 4 s.
- **Groq schemas: no item limits at all.** Even maxItems on arrays keyed to the engine risk keys caused 400 json_validate_failed when the model listed one extra item (6 issues for a 4-issue contract), which made contract review fall back at random. Schemas now have no maxItems, maxLength or key enum; the server keeps only the engine keys and slices lists. Set `AI_DEBUG=1` locally to see Groq error codes in the server log.
- Jsdom harness: wait for `S.db` to leave `'unknown'` before closing the window, or a late `softRender` throws.
- `vercel dev` asks to link a project; the repo uses its own tiny dev server instead.
- **Deploying before setting environment variables:** the first Vercel deploy was done from the import screen without them. Nothing breaks (fallback mode), but a redeploy is needed after adding them. Add variables first next time.
- Pasting secrets into chat: the Groq key and Supabase database password were pasted into a chat during setup. Treated as exposed; rotate them (the user chose to defer).
- The git author on all commits is the user's real name and email (from their git config); the repo may be public.
- Hobby cron: once per day only, may run up to an hour late. Scheduled GitHub Actions are disabled after 60 days of repo inactivity in public repos, which is why Vercel cron was used for keep-alive.
- Browser-pane screenshots time out or catch the page mid-animation; retry. The pane is narrow by default.
- Earlier front-end lessons: hard-coded colours break the themes (use tokens); `.btn` overrides `.burger` display; inline `flex:` styles on inputs break the dictation wrapper.

## 6. Known limits
- Persistence: the profile (photo is a 256 px JPEG data URL in `profiles.preferences.avatar`, 140 KB cap, plan in `preferences.plan`), deals, invoices, proof checklists and signed dates are saved to Supabase and flushed with `keepalive` fetches when the tab is hidden or closed. The user clearing nothing is enough: reopening the site reloads them. Because there is no login, all of it is shared by everyone who has the link.
- `npm run smoke:persist`, `smoke:deals`, `smoke:plan` (run the dev server first) check the photo, deal/invoice and plan rules against the real database and restore what they change.
- No login: everyone who opens the site edits the same demo profile (`demo-ananya`). Writes are validated, capped, rate-limited and same-origin only.
- Per-IP rate limits are per serverless instance (best effort). The daily cap (800 live calls) is counted in the database.
- Free Groq limits (documented at about 30 requests/min, 8K tokens/min, 200K tokens/day for gpt-oss-20b, labelled Developer plan base limits): check your own account.
- Network "Tier 2" data is synthetic placeholder data. Do not present it as market data.
- Speech to text needs Chrome or Edge; Hindi dictation is only understood by the live model.
