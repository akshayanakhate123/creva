# CreVa

A creator-only dashboard for Indian micro-influencers. It values a specific brand offer, flags the rights a contract takes, and drafts a counter for the creator to send. It never accepts, signs or sends anything, and it explains commercial consequences, not legal validity.

`counter.html` is the whole front end and the single source of truth. `public/index.html` is generated from it.

## Run locally

```
npm test        # syntax check, build, output checks
npm run dev     # http://localhost:5173
```

The app works with no network and no keys. Without them it uses its built-in pricing engine and shows an honest "Fallback engine" label.

## Environment variables

Copy `.env.example` to `.env.local` and fill it in. Never commit it.

| Name | Secret | Purpose |
|---|---|---|
| `GROQ_API_KEY` | yes | Live model, called only from the server |
| `GROQ_MODEL` | no | Model name, changeable without code |
| `SUPABASE_URL` | yes | Database URL |
| `SUPABASE_SERVICE_ROLE_KEY` | yes | Server-only database key |

## Layout

```
counter.html        app (source of truth)
public/index.html   generated by scripts/build.js
api/                serverless functions (Vercel /api; mounted locally by server.js)
lib/                shared server code
supabase/           schema.sql, seed.sql
scripts/            build, checks, smoke tests
```

## Deploy

Vercel runs `node scripts/build.js` and serves `public/` plus `api/` (see `vercel.json`).

1. Push this repo to GitHub.
2. In Vercel: Add New, Project, import the repo. Framework preset: Other. Leave the build settings as they are (they come from `vercel.json`: build command `node scripts/build.js`, output directory `public`).
3. Before the first deploy, add these Environment Variables (Settings, Environment Variables), for Production and Preview:

   | Name | Type |
   |---|---|
   | `GROQ_API_KEY` | Secret |
   | `GROQ_MODEL` | Config (value `openai/gpt-oss-20b`) |
   | `SUPABASE_URL` | Secret |
   | `SUPABASE_SERVICE_ROLE_KEY` | Secret |

   Changes to variables only apply to **new** deployments, so redeploy after changing one.
4. Deploy, then run `npm run smoke:live -- https://YOUR-SITE.vercel.app`.

A daily Vercel cron job (`/api/keepalive`, 03:17 UTC, see `vercel.json`) reads one row so the free Supabase project does not pause. A second daily job (`/api/reminders`) marks past-due invoices overdue.

One-time database step for the consent/share feature: run `supabase/migration-002.sql` in the Supabase SQL editor. Everything else works without it. On the free Hobby plan cron jobs can run only once a day and may fire up to an hour late.

See `DEMO-DAY.md` for the demo checklist and `ROLLBACK.md` for rolling back.

## Backend

- `GET /api/health` liveness check.
- `POST /api/ai` the live model (Groq). Tasks: deal, contract, negotiate, autopsy, checker. The engine owns every number; the model only writes explanations. Guardrails (refuse to send/accept) run before any model call. Errors: `bad_request`, `too_large`, `rate_limited`, `upstream_error`, `no_key`, `timeout`.
- `GET /api/data?kind=bootstrap` and `GET kind=metrics` and `POST /api/data?kind=profile|contract|deal|share|event|eval` store the demo user's data in Supabase through the service role key (server only). The profile carries the photo and plan; `deal` carries status, signed date, checklist and invoice.

The app always works without them: any failure falls back to the built-in engine and seeded in-memory data, with an honest label.

Tests: `npm test` (offline, no keys). Live checks: `npm run smoke:ai` (one Groq call), `npm run smoke:data`, and `npm run smoke:persist`, `smoke:deals`, `smoke:plan` (real database; each restores what it changes).

### If the database shows "Demo data (database offline)"

Supabase pauses free projects after a period of inactivity. Open the project in the Supabase dashboard and restore it, wait a minute, then reload the app. The app keeps working on seeded data meanwhile.

### Public demo note

There is no login: everyone who opens the site edits the same demo profile ("demo-ananya"). Writes are validated, size-capped, rate-limited and same-origin only.
